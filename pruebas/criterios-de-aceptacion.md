# Criterios de aceptación para cada aprendizaje

Para considerar aprobado un cambio técnico:
- [ ] No hay datos personales, clientes, precios o información confidencial.
- [ ] Se distingue pedido del cliente de solución cotizada.
- [ ] No se confunde el código de Odoo con la referencia oficial del fabricante.
- [ ] Toda afirmación sobre prestaciones críticas tiene fuente o validación responsable.
- [ ] Una equivalencia no comprobada está marcada «en revisión», no «equivalente».
- [ ] No se inventan códigos ni se conserva stock como dato permanente.
- [ ] Para familia/producto concreto, la respuesta normal incluye código, características y stock **a mano** si se consultó Odoo.
- [ ] «Con explicación» agrega definición y uso breve; sin esa frase, explicación no obligatoria.
- [ ] Se incluye al menos una consulta de prueba reproducible y respuesta esperada.
- [ ] Si cambian instrucciones/skills, se verifica que la versión se haya aplicado en Tuqui y se prueba allí.

**Nota:** las pruebas del repositorio no prueban por sí solas la conexión Odoo/Tuqui; requieren una sesión real del agente.
